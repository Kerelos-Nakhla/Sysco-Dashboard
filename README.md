## 📌 Executive Overview

The **SYSCO Sales & Operations Analytics Dashboard** is an enterprise-grade commercial intelligence system built in Power BI to monitor B2B foodservice wholesale operations. Serving as an executive decision-support and logistics monitoring platform, it synthesizes transactional line items, carrier transit timelines, catalog hierarchies, and corporate client accounts.

The platform monitors **51,302 units shipped** across **2,154 line transactions** and **830 validated purchase orders**, establishing visibility over **$1,265,339.00 in gross sales revenue**, **$64,942.69 in freight logistics investments**, and an outstanding **95.54% on-time fulfillment efficiency**.

   - On the **Sales & Orders Page**, the KPI card displays **+158.71%**, which is mathematically exact: Total Sales of **$1.27M** vs. an un-sliced **SPLY Total Sales Target of $489.10K** ($489,095.51).

   - An on-time delivery rate of **95.54% (793/830 orders)** minimizes customer penalty claims and ensures contract retention.

## 📐 Key DAX Measures & Formula Reference

All business logic is centralized in the dedicated `DAX` table in the Power BI Semantic Model:

### 1. Revenue & Time Intelligence
Calculates commercial sales volume, baseline comparisons, and multi-year growth rates:

```dax
// Total Gross Commercial Sales across all order lines
Total Sales = 
SUM(fact_sales[CC Total Sales])

// Same Period Last Year (SPLY) Sales Benchmark
SPLY Total Sales = 
CALCULATE(
    [Total Sales], 
    SAMEPERIODLASTYEAR(dim_date[Date])
)

// Year-over-Year Growth Percentage
YoY % = 
DIVIDE(
    [Total Sales] - [SPLY Total Sales], 
    [SPLY Total Sales]
)

// Period-to-Date Running Totals
TYTD = TOTALYTD([Total Sales], dim_date[Date])
TQTD = TOTALQTD([Total Sales], dim_date[Date])
TMTD = TOTALMTD([Total Sales], dim_date[Date])
```

### 2. Operational Volume & Supply Chain Metrics
Measures transaction count, fulfillment turnaround, logistics costs, and warehouse counts:

```dax
// Total unique purchase orders
# of Orders = 
DISTINCTCOUNT('dim_order'[Order Key])

// Total catalog products sold
Total Products Sold = 
SUM(fact_sales[Quantity])

// Average order transit time in days
AVG Ship Days = 
AVERAGE(dim_order[CC Ship Days])

// Total freight logistics expenditure
Total Freight = 
SUM(dim_order[Freight])

// Prior-year freight comparison
SPLY Total Freight = 
CALCULATE(
    [Total Freight], 
    SAMEPERIODLASTYEAR(dim_date[Date])
)

// Dynamic Gauge Target Ceiling
MAX Gauge = 2000000
```

### 3. Dimensional Entity Counts
```dax
// Total active corporate accounts
# of Customers = COUNTROWS(dim_customer)

// Active catalog SKU count
# of Products = COUNTROWS(dim_product)

// Global vendor network count
# of Suppliers = COUNTROWS(dim_supplier)

// Commercial sales team headcount
# of Employees = COUNTROWS(dim_employee)

// Category classifications
Count Categories = COUNTROWS(dim_category)
```

## 🏗️ Data Architecture & Star Schema

The enterprise semantic model is engineered as an optimized **Star Schema**:

- **Fact Table:**
  - `fact_sales` — Grain: individual order line items. Contains `Order Key`, `Product Key`, `Unit Price`, `Quantity`, `Discount`, and calculated monetary column `CC Total Sales`.
- **Dimension Tables:**
  - `dim_order` — Order master table containing `Order Key`, `Customer Key`, `Employee Key`, `Order Date`, `Required Date`, `Ship Date`, `Freight`, `Ship Via`, and calculated `CC Ship Days`.
  - `dim_product` — SKU catalog containing `Product Key`, `Product Name`, `Category Key`, `Supplier Key`, `Unit Price`, `Units In Stock`, and reorder thresholds.
  - `dim_category` — Category hierarchy storing `Category Key`, `Category Name`, and descriptions.
  - `dim_customer` — Commercial accounts with `Customer Key`, `Company Name`, address, city, region, postal code, and country.
  - `dim_employee` — Regional commercial sales representatives with `Employee Key`, `Full Name`, title, and territory.
  - `dim_supplier` — Global vendor network with `Supplier Key`, `Company Name`, contact, and country of origin.
  - `dim_date` — Calendar dimension supporting continuous time intelligence (`Year`, `Quarter`, `Month`, `Day`).
  - `DAX` — Dedicated calculation group table holding all centralized DAX measures.
